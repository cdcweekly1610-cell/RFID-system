混凝土試體 RFID 核心追蹤管理 (AI Vision v3.0)

這是一個專為工程品管與實驗室設計的輕量化、純前端網頁應用程式。旨在透過 RFID 晶片追蹤混凝土試體的澆置與試壓排程，並結合 Google Gemini AI 視覺辨識技術，自動解析現場取樣記錄表，大幅減少人工建檔的時間與錯誤率。
        
✨ 核心功能特色

1. 📊 智慧數據儀表板

庫存與狀態總覽：即時顯示標籤總數、已綁定、已試驗（7天/28天）及尚未試驗的試體數量。

動態試壓提醒：自動比對今日日期，提早預告「下次會驗項目」，若為當日則顯示紅色警示，並附註倒數天數。

2. 🏷️ RFID 晶格主導檢視 (Grid View)

群組化顯示：以「表單」為單位，將同批次的 4 顆試體晶片集中顯示於大卡片中。

自動差異標示：同批次 RFID 晶片若有不同，系統會自動使用橘色字體高亮顯示差異處。

拖曳指定 7D 試體：支援 Drag & Drop，可直接將小卡拖曳至指定區塊，快速設定 7 天試壓的試體。

快速跳轉：點擊晶片小卡，自動跳轉至總表並精準過濾出該筆資料。

3. 🤖 AI 拍照智慧辨識 (Gemini OCR)

一鍵辨識：上傳「混凝土取樣記錄表」照片，系統透過 Google Gemini 1.5 Flash 模型，自動提取表單編號、日期、工程部位及 4 顆 RFID 晶片碼。

動態表單：支援彈性勾選該批次實際擁有的試體數量（允許少於 4 顆），未勾選則顯示「無試體」。

日期自動試算：輸入取樣日期後，自動推算並顯示第 7 天與第 28 天的實驗室試壓日。

4. 📅 實驗室排程行事曆

今日任務清單：列出當天必須進行試壓的對應表單與試體編號。

14 日近期排程：以表格條列未來兩週內的品管行程，方便實驗室預先安排工作。

5. 🔗 Webhook 自動化同步

Make.com 串接：在新增表單時，系統會在背景自動將資料封包送至 Make.com 的 Webhook，可輕易接續自動寫入 Notion 或其他資料庫。

🛠️ 技術架構與依賴

前端框架：純 HTML5, Vanilla JavaScript (無須編譯或伺服器)

UI 樣式：Tailwind CSS (透過 CDN 引入)

圖示庫：FontAwesome 6.4.0

AI 辨識：Google Gemini API (gemini-1.5-flash)

資料儲存：瀏覽器本地端儲存 (localStorage)

🚀 快速開始與環境設定

由於本系統為純前端架構，不需要安裝任何後端伺服器或資料庫。只需用瀏覽器開啟 index.html 即可運行。

⚠️ 重要設定步驟 (必讀)

要讓系統的 AI 照片辨識功能 與 Webhook 外部同步功能 正常運作，您需要修改 index.html 內的兩個參數：

1. 設定 Gemini API Key (啟動 AI 功能)

請在 index.html 檔案中搜尋 handleImageUpload 函式，找到以下段落並填入您的金鑰：

// 請替換為您真實且有效的_API_KEY
const apiKey = "請替換為您的_API_KEY"; 


若尚未擁有 API Key，請前往 Google AI Studio 免費申請。

2. 設定 Make.com Webhook (啟動資料同步)

請在 index.html 檔案中搜尋 handleFormSubmit 函式，找到以下段落，確認或替換為您專屬的 Webhook URL：

// Sync to Make Webhook
const webhookUrl = "https://hook.eu1.make.com/s8xfpuham4pgw6boorsijykpd1hp9hs0";


資料送出格式為 JSON，包含表單號碼、日期、工程資訊及試體陣列，您可以在 Make.com 中解析並綁定至 Notion。

💡 使用說明

初次使用：網頁載入時若無資料，會自動寫入內建的 4 筆示範資料供測試。您可以點擊右上角「重新載入示範記錄表」隨時重置。

資料新增：切換至「拍照 AI 辨識新增」頁籤，拖曳照片至虛線框內，等待 AI 填寫完畢後點擊儲存。

指定 7D 試體：在「RFID 晶片晶格檢視」頁籤中，找到尚未指定的表單，將白色的試體小卡拖曳到下方的虛線框內即可完成綁定。

刪除資料：在「完整表單與試體清單」頁籤中，點擊列表最右側的垃圾桶圖示即可刪除整筆表單紀錄。

⚠️ 注意事項

資料安全性：目前的資料皆儲存於使用者本機瀏覽器的 localStorage 中。若清除瀏覽器快取，資料將會遺失。強烈建議透過 Webhook 功能將重要資料同步至 Notion 進行永久備份。

CORS 限制：由於純前端限制，本系統無法「直接」利用 API 從 Notion 讀取資料，需透過 Make.com 進行單向或雙向的中繼處理。
